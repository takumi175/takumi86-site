自宅サーバーに最初に載せたのが Pi-hole だった。効果が体感しやすく、必要なリソースも少ない。LXC コンテナに 512MB 割り当てれば動く。

## Pi-hole とは何か

広告ブロッカーというより、**「嘘をつく DNS サーバー」**と考えると分かりやすい。

スマホが `ads.example.com` にアクセスしようとすると、まず DNS に「そのIPアドレスは？」と尋ねる。Pi-hole はこの問い合わせを受けて、広告配信ドメインのリストと照合する。

- リストに**ない** → 通常通り上流の DNS に転送して、正しい IP を返す
- リストに**ある** → `0.0.0.0` を返す

`0.0.0.0` は「どこでもない場所」なので、端末は広告サーバーに接続できない。結果として広告が表示されない。

### ブラウザ拡張との違い

**全端末に効く。** ルーターの DNS 設定を Pi-hole に向ければ、スマホ・タブレット・テレビ・ゲーム機まで、家の Wi-Fi に繋がる全機器が対象になる。拡張機能を入れられないデバイスにも効くのが最大の利点だ。

**アプリ内広告にも効く。** スマホゲームやニュースアプリの広告が消えることがある。

### 苦手なこと

**YouTube の広告は消せない。** 動画と同じドメインから配信されているため、ブロックすると動画本体も見られなくなる。Instagram や Facebook の広告も同様。

**サイトが壊れることがある。** 広告と一体化した機能をブロックしてしまい、正常に動かなくなるケースがある。その場合は個別にホワイトリスト登録が必要。

## コンテナを作る

Proxmox の管理画面から `CTを作成`。

| 項目 | 値 |
|---|---|
| CT ID | 100 |
| ホスト名 | `pihole` |
| テンプレート | `debian-13-standard_13.6-1_amd64` |
| ディスク | 8 GB |
| CPU | 1 コア |
| メモリ / スワップ | 512 / 512 MB |
| IPv4 | **静的** `192.168.11.101/24` |
| ゲートウェイ | `192.168.11.1` |

**IPは必ず静的にする。** DNS サーバーの IP が変わると、参照している全端末が名前解決できなくなる。DHCP で運用すると事故のもとだ。

テンプレートを選ぶときに一つ注意点がある。GUI の一覧にはアーキテクチャの列がなく、同じ名前で amd64 と arm64 が並んでいるだけなので判別できない。私は最初に arm64 を落としてしまった。

シェルから確認するのが確実だ。

```
$ pveam available --section system | grep debian-13
system  debian-13-standard_13.6-1_amd64.tar.zst
system  debian-13-standard_13.6-1_arm64.tar.zst
```

## Pi-hole をインストール

コンテナのコンソールから、

```
apt update && apt upgrade -y
apt install -y curl
curl -sSL https://install.pi-hole.net | bash
```

対話式のインストーラが立ち上がる。回答は以下の通り。

| 質問 | 回答 |
|---|---|
| Upstream DNS Provider | `Cloudflare` |
| Blocklists | 既定のまま |
| Admin Web Interface | On |
| Web Server (lighttpd) | On |
| Log queries | **On** |
| Privacy mode | `Show everything` |

### ログを有効にする理由

**トラブル時に原因が分からなくなる。** サイトが正常に表示されないとき、ログを見れば原因のドメインが特定でき、ホワイトリストに追加して直せる。ログがないと手がかりがない。

もう一つ、**家の中の通信が可視化される**のが面白い。スマートテレビやスマホアプリが裏で何と通信しているかが見える。DNSの動きを実物で観察できる教材にもなる。

プライバシーを気にする共用環境なら無効にする選択もあるが、個人利用なら有効にしておく方が実用的だ。

インストール完了時に**管理画面のパスワードが一度だけ表示される。** 控え忘れると後から変更が必要になるので注意。

## ブロックリストが読み込まれない場合

インストール直後、管理画面で `Domains on Lists: Error (-2)` と表示されることがある。ブロックリストのダウンロードに失敗した状態だ。

```
pihole -g
```

これでリストを取得し直せる。数分後、`Domains on Lists` に 8万件前後の数字が入れば成功。

## DNSを向ける

**まずは自分の端末だけで試すのが安全。** 家族がいる環境で、いきなり全体に適用すると、何か動かなくなったときに原因が分からず混乱する。

Windows の場合、

1. `設定` → `ネットワークとインターネット` → `Wi-Fi`
2. 接続中のネットワークをクリック
3. `DNS サーバーの割り当て` の `編集`
4. `自動 (DHCP)` → **`手動`**
5. `IPv4` をオンにして、優先DNSに `192.168.11.101`
6. 代替DNSは**空欄のまま**

### 代替DNSを空にする理由

ここに `8.8.8.8` などを入れると、Windows が気まぐれにそちらを使ってしまい、Pi-hole を素通りすることがある。空にしておけば必ず Pi-hole を経由する。

万一 Pi-hole が止まるとネットが使えなくなるが、そのときは設定を `自動` に戻せば復旧する。

しばらく使って問題がなければ、ルーターの DHCP 設定で配布する DNS を Pi-hole に変えれば家全体に適用される。

## 動かしてみて

導入直後の1時間で、47件のクエリのうち11件がブロックされた。ブロック率 23.4%。一般的には5〜15%程度と言われるので、高めの数字だった。

Query Log を眺めると、Chrome が数秒おきにこんな問い合わせをしているのが見える。

```
09:52:47  beacons5.gvt3.com (blocked beacons.gvt2.com)   13.6 μs
09:52:44  beacons5.gvt3.com (blocked beacons.gvt2.com)    9.3 μs
09:52:42  beacons5.gvt2.com                               9.5 μs
09:52:42  beacons4.gvt2.com                              14.5 μs
09:52:40  beacons3.gvt2.com                               9.8 μs
09:52:38  beacons2.gvt2.com                               9.1 μs
09:52:36  beacons.gvt2.com                                7.4 μs
```

Google のテレメトリ用ドメインだ。ブロックされたので代替ホストを次々に当たっている様子が読み取れる。

`beacons5.gvt3.com (blocked beacons.gvt2.com)` という表記は、CNAME を辿った先がブロック対象だったという意味。DNS の動きが具体的に見えて面白い。

応答時間が **7〜14マイクロ秒**なのも注目に値する。ブロック時はリストを引いて即答するだけなので、外部に問い合わせる場合（数十ミリ秒）と比べて桁違いに速い。

## 運用上の注意

**Pi-hole が止まるとネットが使えなくなる。** これが最大のリスクだ。コンテナを再起動したり、Proxmox 本体をメンテナンスしたりする間、DNS が引けなくなる。

対策は2つある。

**① スナップショットと自動起動を設定する。** Proxmox の `オプション` → `起動時の自動起動` を有効にしておけば、停電や再起動のあとも自動で立ち上がる。BIOS の `Auto Power On` と組み合わせれば、停電からの復旧が無人で完結する。

**② セカンダリを立てる。** ラズパイなど別の機械にもう一台 Pi-hole を置いて、ルーターの代替 DNS に設定する。片方が落ちても大丈夫になる。本格運用するならこちらが正しい。

私はまだ①だけの状態だが、いずれ②もやる予定だ。

## スナップショットを取っておく

Proxmox の利点はここにある。設定が固まった時点でスナップショットを取っておけば、何か壊しても数秒で戻せる。

`100 (pihole)` → `スナップショット` → `スナップショット採取`。名前は `pihole-ok` のように、何の時点か分かるものにしておく。

試しに `pihole disable` でブロックを無効にしてから、スナップショットにロールバックしてみた。コンテナが一度停止して、2秒でスナップショット時点の状態に戻った。

ただし**ロールバック後は自動起動しない**ので、`開始` ボタンを押す必要がある。この間ネットが使えないので、DNS を向けている端末では注意が必要だ。
